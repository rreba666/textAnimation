# 开发中遇到的重难点

## 一、Zustand Selector 响应式陷阱

### 问题
Habits 点击打卡后 UI 不更新，必须刷新页面。

### 根因
```ts
// 错误：订阅函数引用（稳定不变，永不触发重渲染）
const getWeekRecords = useDashboardStore((s) => s.getWeekRecords)
```
Zustand 用 `Object.is` 比较 selector 返回值。函数引用永远相等，组件永不重渲染。

### 修复
```ts
// 正确：订阅数据源
const habitRecords = useDashboardStore((s) => s.habitRecords)
const { getWeekRecords } = useDashboardStore.getState() // 渲染时取值
```

## 二、TailwindCSS 3 硬编码 CSS 变量

### 问题
暗色模式下 `text-text-secondary` 颜色不跟随主题变化。

### 根因
TailwindCSS 3 JIT 引擎在构建时将 `var(--text-primary)` 解析为实际值 `rgb(74 74 74)`，而非保留变量引用。

### 修复（四步）

**1. CSS 变量从 hex 改为 RGB 通道**
```css
:root { --text-primary: 74 74 74; } /* 不是 #4A4A4A */
```

**2. Tailwind config 用标准格式**
```js
text: { primary: 'rgb(var(--text-primary) / <alpha-value>)' }
```

**3. 所有直接引用包裹 rgb()**
```css
body { color: rgb(var(--text-primary)); }             /* CSS */
className="bg-[rgb(var(--check-undone))]"             /* Tailwind 任意值 */
fill="rgb(var(--accent-green))"                       /* SVG */
style={{ background: 'rgb(var(--bg-code))' }}         /* 内联 */
```

**4. 末尾添加覆盖规则兜底**
```css
.text-text-primary, .text-text-secondary, .text-text-light { color: inherit !important; }
```

## 八、GSAP 交互动画集成

### 动画选型
选用 GSAP 3.15 替代 CSS animation / transition：
- **弹性缩放**（打卡圆点）：CSS `transition` 难以实现回弹效果，GSAP `back.out(3)` + `yoyo` 一行搞定
- **入场动画**（待办滑入）：需在 DOM 挂载后立即触发，GSAP `.from()` 自动记录最终状态再反向播放
- **脉冲反馈**（快捷键）：需要 scale + boxShadow 多属性并行，GSAP `fromTo` 一个 tween 完成

### 待办入场动画时序
```
addTodo() → Zustand set() → React re-render → DOM 挂载
                                              ↓
                            useEffect(todos.length) → requestAnimationFrame → gsap.from(el)
```
关键点：`requestAnimationFrame` 确保 DOM ref 已挂载后再调用 GSAP，避免 `el` 为 null。

### 键盘快捷键架构
```
App.tsx keydown → window.dispatchEvent(CustomEvent)
                        ↓
    Todo.tsx 监听 shortcut:focus-todo / shortcut:edit-todo
    Notes.tsx 监听 shortcut:focus-note
```
- 使用 CustomEvent 解耦：各组件自主决定如何处理快捷键，App 层不持有子组件 ref
- 输入区检测：`tagName === 'INPUT' || 'TEXTAREA' || isContentEditable` 时跳过，避免干扰正常打字
- Notes 的 N 快捷键涉及"先 create 再 focus"的异步流程，通过 `shouldFocusTitle` ref 标记 + `useEffect(selectedNote)` 实现两步串联

## 九、删除撤销（Toast + GSAP 动画）

### 动画时序

```
点击删除 → gsap.to(el, { opacity:0, height:0, padding:0, 0.3s })
                ↓ onComplete
         deleteTodo(id) + showToast({ onUndo })
                ↓
    3s内撤销 → addTodo(text) + toggleTodo(if completed) → 入场动画自动播放
    超时3s  → dismissToast() 出场动画
```

关键点：
- 删除前快照 `{ text, completed }` 存入闭包，撤销时完整恢复
- `deletingIds` Set 防止动画期间重复点击导致的重复删除
- `el.style.overflow = 'hidden'` 必须在动画开始前设置，否则内容溢出

### Toast 全局单例模式

```
showToast() → 全局函数引用 → ToastContainer.setState()
                                  ↓
                      useEffect → GSAP 入场动画 + setTimeout 自动消失
```

- 模块级 `showToastFn` 变量：确保同一时间只有一个 Toast
- 新 Toast 到达时：先 `clearTimeout` + `kill()` 旧动画，再替换数据
- 撤销流程：`clearTimeout` → `onUndo()` → `dismissToast()` 出场动画

### 撤销恢复的数据一致性

撤销时使用 `useDashboardStore.getState()` 而非 hook 闭包中的 action 引用，避免 stale closure：
```ts
store.addTodo(snapshot.text)
if (snapshot.completed) {
  const restored = store.todos[store.todos.length - 1]
  if (restored) store.toggleTodo(restored.id)
}
```
Zustand `set()` 是同步的，`addTodo` 后立即可以从 `getState()` 取到新增的待办。

## 十一、HTML5 拖拽排序实现要点

### 架构
```
拖拽事件(onDragStart/Over/Leave/Drop/End) → 状态(dragId/dragOverId) → 视觉反馈(className) → reorderTodos(action)
```

### 关键设计决策

1. **ID 交换而非索引交换**：`reorderTodos(fromId, toId)` 在 `todos` 全量数组中按 ID 查找位置再 splice，保证筛选视图下仍正确
2. **编辑模式禁用拖拽**：`draggable={editingId !== todo.id}` 避免拖拽与文本选择冲突
3. **透明度优先级**：拖拽中的项用 `opacity-40`，完成项非拖拽时用 `opacity-60`，用三元表达式合并
4. **目标指示器**：`dragOverId` 匹配时该 `<li>` 顶部出现 `border-t-2 border-[rgb(var(--accent-primary))]`，配合 `-mt-[2px]` 抵消边框占位
5. **落地动画**：`handleDrop` 中 `requestAnimationFrame` 等待 React 重渲染后，GSAP `fromTo(scale 1.04→1)` 播放脉冲

### Toast 倒计时进度条

GSAP 动画 `width: 100% → 0%`，`linear` 缓动，duration 与 Toast 存活时间一致：
```ts
progressTweenRef.current = gsap.to(progressRef.current, {
  width: '0%', duration: dur, ease: 'linear',
})
```
新 Toast 到达时 `progressTweenRef.current.kill()` 终止旧动画，进度条重置为 100% 并重新开始。

## 十二、加载骨架屏（Skeleton Screen）

### 为什么需要骨架屏

本应用使用 Zustand persist + localStorage，数据 hydration 是同步的，理论上没有加载延迟。但骨架屏作为首屏体验优化仍有价值：
1. 首次访问时组件树挂载需要时间（React 渲染 + 布局计算）
2. 骨架屏提供视觉上的"加载反馈"，避免白屏闪烁
3. 属于 UI 润色，提升品质感

### 实现方式

```
App 挂载 → phase='skeleton' → DashboardSkeleton 渲染（Shimmer 流光循环）
              ↓ 700ms 最短展示
         GSAP.to(skeletonRef, opacity:0, 0.3s)
              ↓ onComplete
         setPhase('content') → 内容层渲染
              ↓ useEffect
         GSAP.fromTo(contentRef, opacity:0→1, y:10→0, 0.4s)
```

### Shimmer 流光动画

每个占位块内部有一个 `absolute` 定位的子元素，GSAP 驱动 `left` 属性从 `-50%` 到 `100%` 循环：

```tsx
const tl = gsap.timeline({ repeat: -1 })
tl.fromTo(el, { left: '-50%' }, { left: '100%', duration: 1.8, ease: 'power2.inOut' })
```

- 子元素宽度 50%，`skew-x-[-15deg]` 斜切
- 背景：`linear-gradient(transparent → rgba(255,255,255,0.22) → transparent)`
- 父元素底色：`rgb(var(--check-undone))`，自动适配亮/暗主题

### 卡片占位设计

每张骨架卡片使用 `card` 类（与真实卡片相同的圆角/边框/阴影），内部按真实布局摆放 `Shimmer` 块：
- **Todo**：标题圆+矩形、3 筛选标签、进度条、输入框、5 行复选框
- **Habits**：标题、2 视图按钮、5 行 × 7 打卡圆点
- **Links**：标题、3×2 favicon 网格
- **Pomodoro**：标题、大圆环、3 预设按钮
- **WeekStats**：标题、2×2 统计卡片
- **Calendar**：标题、月份导航、7×5 日期网格
- **Notes**：标题、左侧 4 笔记卡片 + 右侧大编辑区

### 为什么不用 display:none 控制

骨架屏和内容层通过 `phase` 状态互斥渲染，而非同时挂载用 CSS 控制可见性：
- 避免两套 DOM 同时存在导致的双倍布局开销
- 过渡通过 GSAP `onComplete` 回调精确串行：先骨架淡出完毕，再内容淡入
- 骨架层在 `opacity: 0` 动画完成后随组件卸载自然消失

## 十三、周报弹窗（Modal + Recharts）


```tsx
requestAnimationFrame(() => {
```

## 十四、弹窗退场动画（GSAP closing 状态机）

### 问题
之前的弹窗直接调用 `onClose()` 卸载组件，弹窗瞬间消失，体验生硬。

### 方案
引入 `closing` 状态机，将关闭拆分为两个阶段：

```
点击关闭 → setClosing(true) → GSAP 退场动画播放(0.3s)
                                    ↓ onComplete
                              onClose() → 父组件 setOpen(false) → unmount
```

### 实现要点

```tsx
const [closing, setClosing] = useState(false)

const handleClose = useCallback(() => {
  if (closing) return  // 防止重复触发
  setClosing(true)
  gsap.to(modalRef.current, {
    opacity: 0, y: -20, scale: 0.95,
    duration: 0.3, ease: 'power2.in',
    onComplete: () => { setClosing(false); onClose() }
  })
}, [closing, onClose])
```

- `closing` 作为动画锁，阻止动画期间再次触发
- `useCallback` 依赖 `closing` 和 `onClose`，确保 ESC 事件监听的引用稳定
- 入场动画增加 `!closing` 守卫：`if (!open || closing) return`
- 每次 `open` 变为 true 时重置 `closing = false`

### Portal 与退场动画的兼容

Portal 渲染到 `document.body`，退场动画仍正常工作，因为 GSAP 直接操作 ref 对应的 DOM 节点，与组件在 React 树中的位置无关。

### 月度折线图的 X 轴标签间隔

月份天数不固定（28-31），使用动态间隔确保显示约 7 个标签：
```ts
const xInterval = Math.max(1, Math.floor(daysInMonth / 7))
// 31天→4, 30天→4, 29天→4, 28天→4
```

```
输入：选中年份 year
1. 计算 gridStart = year-01-01 所在周的周一
2. 计算 gridEnd = year-12-31 所在周的周日
3. eachDayOfInterval 生成所有日期
4. 按 ISO 周号分组 → weeks[weekIndex][dayIndex]
5. 每个单元格 = { date, count: habitRecords[date].length }
```

### 空白填充

年初第一周和年末最后一周可能不足 7 天，对应位置渲染空 `<div>` 占位。按 `week[row]` 取值，若为 `undefined` 则渲染透明占位块。

### 颜色映射

```ts
function heatmapColor(count: number): string {
  if (count === 0) return 'rgb(var(--check-undone))'  // 无打卡：底色
  const alpha = 0.15 + Math.min(count / 8, 1) * 0.75    // 1次→0.24, 8次+→0.90
  return `rgba(var(--accent-primary), ${alpha.toFixed(2)})`
}
```

CSS 变量在 `rgba()` 中的逗号分隔语法为 CSS Color Level 4，现代浏览器均支持。

### 月标签定位

每月第一天距 `gridStart` 的天数差 ÷ 7 = 所在列索引。跳过与前一个标签间距 < 3 列的标签，避免小月份重叠。

### 数据导入导出的 Zustand 集成

```ts
// 导出：直接序列化 getState() 的数据部分
const data = { version: 1, todos, habits, ... }
JSON.stringify(data) → Blob → download

// 导入：setState 覆盖后 reload
const store = useDashboardStore.getState()
Object.assign(store, parsedData)
useDashboardStore.setState({ ...store })
window.location.reload()  // 确保 persist 写入 + React 全量重渲染
```

使用 `window.location.reload()` 而非细粒度更新，因为：
1. persist 中间件需要完整 hydration 周期
2. 多个关联状态同时变更，逐字段更新易出现不一致
3. 用户触发导入频率极低，reload 成本可接受

## 十八、dnd-kit 拖拽排序迁移

### 选型原因

从 HTML5 原生 DnD 迁移到 `@dnd-kit`：
1. 原生 DnD 移动端完全不支持，dnd-kit 的 `PointerSensor` 统一鼠标和触摸
2. 原生 DnD 不支持键盘操作，dnd-kit 内置 `KeyboardSensor`
3. 原生 DnD 的拖拽预览无法自定义样式，dnd-kit 提供 `DragOverlay` 组件
4. dnd-kit 的 `useSortable` 自动处理 transform 动画，无需手动管理 CSS transition

### DragOverlay 与 GSAP 协同

```tsx
// 拖拽开始时 DragOverlay 入场
handleDragStart → setActiveId → requestAnimationFrame
              → gsap.fromTo(overlayRef, { scale: 0.9 }, { scale: 1.03, back.out(2) })

// 拖拽结束后卡片回弹
handleDragEnd → arrayMove → setActiveId(null)
             → 双层 requestAnimationFrame（等 dnd-kit transition 完成）
             → querySelector(`[data-card-id="${id}"]`)
             → gsap.fromTo(el, { scale: 1.04 }, { scale: 1, elastic.out(1, 0.3) })
```

双层 `rAF` 原因：第一帧等 React 重渲染（`setActiveId(null)` 触发 `useSortable` 更新 transform），第二帧确保 dnd-kit 的 CSS transition 已开始执行。

### 传感器配置

```tsx
const sensors = useSensors(
  useSensor(PointerSensor, { activationConstraint: { distance: 8 } }),
  useSensor(KeyboardSensor, { coordinateGetter: sortableKeyboardCoordinates }),
)
```

- `distance: 8`：8px 移动阈值，小幅度点击不触发拖拽，避免与复选框/按钮交互冲突
- `KeyboardSensor`：Tab 聚焦后空格拾取、方向键移动、回车/空格放下

### 滚动容器内 dnd-kit 的 DragOverlay 错位问题

在 `overflow-y-auto` 滚动容器内使用 `DragOverlay` 时，浮层会偏移到鼠标右下方。原因：

1. `DragOverlay` 使用 `position: fixed` 渲染到 viewport
2. dnd-kit 的坐标计算基于 `DndContext` 所在坐标系的 rect
3. 滚动容器内的元素 rect 是相对滚动容器的，而非 viewport
4. `DragOverlay` 用这个相对坐标去 viewport 定位 → 偏移

解决方案：移除 `DragOverlay`，依赖 `useSortable` 的 transform 平移 + opacity 反馈。为避免 `useSortable` 的 `scaleX/scaleY` 挤压元素，手动构造 transform 只取 translate：

```tsx
transform: transform
  ? `translate3d(${transform.x}px, ${transform.y}px, 0)`
  : undefined
```

### Service Worker 缓存策略

```

激活(activate) → 清理旧版本缓存
请求(fetch)   → 静态资源(.js/.css/.svg/.ttf)：缓存优先 + 后台更新
              → 其他请求：网络优先 → 离线回退 index.html
```

### 安装按钮显示逻辑

```ts
const showInstallBtn = !installed && (!!installPrompt || hostname === 'localhost')
```

- `beforeinstallprompt`：Chrome/Edge HTTPS 下触发，提供 `prompt()` 方法
- `appinstalled`：安装完成后隐藏按钮

### 确认弹窗函数式调用

```ts
// 模块级闭包 + Promise 实现异步等待
let showFn: ((opts) => void) | null = null

export function showConfirm(opts): Promise<boolean> {
  return new Promise((resolve) => showFn?.({ ...opts, resolve }))
}
```

- `cancelText: ''` 传空字符串隐藏取消按钮（单按钮模式）
- ESC / 遮罩层点击 → `resolve(false)`

### 三层阴影模拟纸张堆叠

```css
  0 1px 3px rgba(0,0,0,0.06),   /* 近层：紧贴桌面 */
```

### 图钉色彩方案

6 种低饱和度彩色（暖粉/淡蓝/浅绿/米黄/淡紫/杏色），使用 `radial-gradient` 模拟金属高光，根据卡片 ID 哈希分配。拖拽时替换为 SVG 虚线圆圈（`strokeDasharray="2 1.5"`）模拟钉孔。

### 提醒弹窗的滚动容器裁剪问题

待办列表在 `overflow-y-auto` 容器内，绝对定位弹窗被裁剪。解决方案：`createPortal` 渲染到 `document.body`，点击铃铛时 `getBoundingClientRect()` 计算 viewport 坐标，`requestAnimationFrame` 延迟一帧等 Portal 挂载后定位。

### 首次访问弹窗时序

骨架屏 700ms + 卡片入场 stagger 0.7s ≈ 1.4s，弹窗延迟从 1.5s 调整到 2s，确保弹窗在卡片入场动画完成后出现。

## 二十一、纯 CSS 装饰系统

### 设计理念

所有装饰元素（书脊阴影、装订孔、和纸胶带、折角、纸张堆叠）均使用 CSS 实现，零 JS 运行时开销，`pointer-events: none` 不干扰交互。

### 书脊阴影

`main-wrapper::before/::after` 各 40px 宽，`position: fixed` 覆盖全屏，`linear-gradient` 从 `rgba(0,0,0,0.04)` 渐隐至透明，模拟翻开书本内页的微弱凹陷。

### 装订孔

`fixed left:10px`，4 个 14px 圆环用 `space-evenly` 纵向分布，`border: solid rgb(var(--check-undone))` 跟随主题色，暗色模式下自动变为 78 紫灰色可见。

### 和纸胶带

`fixed` 右上角，`rotate(10deg)` 斜贴，`repeating-linear-gradient` 模拟和纸条纹 + 暖粉绿渐变。

### 光斑漂移

3 个 `radial-gradient` 光斑 + 底层波动渐变，纯 CSS `@keyframes` 驱动 18-25s 慢速循环。订阅 store `theme` 自动切换阳光/月光色。
