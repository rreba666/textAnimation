### 第十一次迭代：dnd-kit 拖拽排序

**新增依赖**：`@dnd-kit/core` 6.3.1 / `@dnd-kit/sortable` 10.0.0 / `@dnd-kit/utilities` 3.2.2

| 文件 | 改动 |
|------|------|
| `src/App.tsx` | 移除 HTML5 DnD，迁移到 dnd-kit：`DndContext` + `SortableContext` + `useSortable` + `DragOverlay` |

dnd-kit 架构：
```
DndContext (PointerSensor 8px阈值 + KeyboardSensor)
  └── SortableContext (rectSortingStrategy)
        ├── SortableCard ← useSortable({ id })
        └── ...
  └── DragOverlay ← 被拖拽卡片浮动副本
```

迁移对比：

| 项目 | HTML5 DnD | dnd-kit |
|------|-----------|---------|
| 碰撞检测 | 手动 ID 匹配 | `closestCenter` |
| 拖拽预览 | 浏览器幽灵图 | `DragOverlay` 组件副本 |
| 键盘支持 | 无 | `KeyboardSensor` + 方向键 |
| 位移动画 | 手动 CSS | `useSortable` transform + transition |
| 排序算法 | 手动 splice | `arrayMove` 工具函数 |

拖拽动画：DragOverlay 入场 `back.out(2)` 弹出 → 原位 `opacity:0.35` → 松手 GSAP `elastic.out` 回弹

### 待办 dnd-kit vs 卡片 dnd-kit 差异

| 特性 | 卡片 | 待办 |
|------|------|------|
| DragOverlay | 使用（浮层副本 + GSAP 入场缩放） | 不使用（滚动容器内坐标系冲突） |
| 视觉反馈 | `useSortable` opacity + DragOverlay | `useSortable` opacity 0.3 + transform 平移 |
| transform | `CSS.Transform.toString` 全量 | 仅 `translate3d(x, y, 0)` 忽略 scale |
| 策略 | `rectSortingStrategy` | `rectSortingStrategy` |
| 传感器 | PointerSensor(8px) + KeyboardSensor | PointerSensor(5px) |

### 为什么待办不用 DragOverlay

`DragOverlay` 通过 `position: fixed` 渲染到 viewport，但 `DndContext` 在滚动容器 (`overflow-y-auto`) 内部时，dnd-kit 计算的坐标基于滚动容器，导致浮层偏移到鼠标右下方。提升 `DndContext` 到卡片层级仍无法解决（`SortableContext` 的 rect 测量仍受滚动影响）。移除 `DragOverlay`，依赖 `useSortable` 自带的 transform 平移 + opacity 反馈，效果等效且无错位。
